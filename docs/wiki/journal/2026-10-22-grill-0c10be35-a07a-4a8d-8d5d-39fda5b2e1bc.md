## Question 20

```text
Round: Linux distribution boundary
Question: How should Fungi handle Linux systems that require installation to run Chromium's sandbox?
Description (Markdown source):
The foundation now has a small, unchanged four-method authoring API, broader browser rendering, durable drafts/artifacts, and automated platform checks. One distribution conflict remains.

| Tested Linux environment | Observed result |
| --- | --- |
| Ubuntu 22.04 hosted desktop | Session workflow and 20 rendering checks pass; WebGL is unavailable on the virtual display |
| Ubuntu 24.04 hosted desktop | The portable renderer aborts before opening because its sandbox cannot start under the default host policy |

Ubuntu 24.04 restricts unprivileged user namespaces. Chromium then requests a root-owned sandbox helper. Supporting this environment through a system package or an application-specific policy adds an installation/setup step. We have not changed machine security settings or disabled the renderer sandbox.

This is a real choice between the original no-install promise and wider Linux coverage. Cross-platform core tests already pass, but that alone does not establish desktop renderer support.

Sources: [observed CI run](https://github.com/rengwu/fungi/actions/runs/39752716551), [Ubuntu AppArmor documentation](https://documentation.ubuntu.com/security/security-features/privilege-restriction/apparmor/).
Recommendation: Keep the portable, no-install default and claim only Linux environments that pass the desktop checks. Make unsupported launches clear. Add an optional Linux package later if its wider reach is worth maintaining another distribution path.
Options: Keep no-install; support explicitly verified Linux environments / Allow an optional Linux installation/package path for wider support / Focus on macOS and Windows first; defer Linux desktop UI support
Selected: Keep no-install; support explicitly verified Linux environments
```
