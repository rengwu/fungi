## Question 16

```text
Round: Reliable agent return: remaining decisions
Question: May automatic return require an explicitly enabled integration for harnesses whose built-in tools cannot wait long enough?
Description (Markdown source):
The Go + Electron prototype now supports HTML, flat forms, pasted/selected images, saved drafts, cancellation and crash recovery. Five installed harnesses returned real Fungi helper results without repeated model checks. Claude, Grok and Pi passed three-minute waits; those tests do not establish arbitrary AFK reliability.

There is a concrete compatibility issue: the tested OpenCode 1.18.34 uses bounded Bash execution. OpenCode's v2 documentation describes a background shell with completion notifications and no default timeout, but that is a different tool contract from the installed v1 configuration. We should prefer native capabilities wherever they work.

An optional Fungi integration could bind the exact originating conversation and deliver one completion event. Depending on the harness, the user would explicitly load a bundled plugin or startup configuration. That adds a setup step for that harness, though Fungi itself would still be a portable folder with no installer or separately installed runtime. This would not require a general plugin framework for UI authors.

If setup is forbidden, support must depend on suitable built-in harness capabilities; unsupported versions would use the already accepted manual ‘done’ fallback and would not count as verified automatic return. No harness configuration has been changed.

Sources: [OpenCode Bash implementation](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/tool/bash.ts), [OpenCode v2 background shell](https://dev.opencode.ai/v2/docs/tools/), [OpenCode plugins](https://opencode.ai/docs/plugins/).
Recommendation: Allow a thin, explicitly enabled integration only where native mechanisms are insufficient. Keep skill authoring unchanged, preserve manual fallback, and verify exact-session delivery before claiming support.
Options: Allow optional, explicitly enabled harness integrations where needed / Require no harness setup; use manual fallback on unsupported versions
Selected: Require no harness setup; use manual fallback on unsupported versions

```
