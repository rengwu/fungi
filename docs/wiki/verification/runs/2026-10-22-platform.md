# Rendering flexibility and foundation repairs

The user requested autonomous work toward a stable, robust, simple and broadly
flexible platform. This run covers [FEAT-sessions](../../features/sessions.md)
and [FEAT-interfaces](../../features/interfaces.md): lifecycle defects, ordinary
browser capabilities, a separate skill-owned comparison UI, and the remaining
rich-grill image/retry scenarios. The selected local and container checks
passed. **Windows and Linux desktop execution are outside this pass;
cross-packaged builds remain unverified on their target desktops.**
Later [hosted platform checks](2026-10-22-hosted.md) have their own verdict
and do not expand the scope of this earlier pass.

## Build and environment

Work is based on `eca3d85` with local changes. The [manifest](../../evidence/2026-10-22-platform/manifest.json)
fingerprints source, binaries and three prepared packages. Native UI journeys
used the development executable on macOS 27.0 arm64 (26A5368g), Go 1.26.4 and
Electron 44.9.0. They preceded the later helper-write and platform-file repairs;
their binary and unchanged renderer hashes are recorded separately. The final
packaged renderer check uses
`dist/fungi-darwin-arm64-2026-10-22T08-33-53-221Z/fungi` and the final Go source.

The Linux core run uses the existing official Go image pinned by digest, under
OrbStack. Its [command](../../evidence/2026-10-22-platform/linux-command.json)
disables networking, uses UID/GID 65534, mounts only copied source read-only and
removes its test container on exit. OrbStack was initially stopped and was
started through its installed app. No new VM or Windows connection was created.

Automated fixtures use one pending CLI call. Native tests use manual receipts
and one collection after observed completion. No model polling, additional
callback waiter, authentication or harness configuration change was used.

## Defects and changes

[Baseline observations](../../evidence/2026-10-22-platform/regressions.json)
record reproduced failures rather than treating earlier demos as exhaustive:

- Blob conversion preceded main-process ordering, allowing newer calls to
  overtake older image saves. The preload now orders mutations before
  conversion, checks total Blob size before allocation, and permits retry.
- Exact-limit JSON could be acknowledged but unreadable because its newline
  exceeded the read limit. Publication counts that byte. Renderer messages
  also check the full envelope before sending, so metadata overhead cannot
  terminate the helper protocol.
- Malformed/closed stdout could block the owner in `Wait`. The owner now ends
  the broken protocol and drains complete messages before interpreting exit.
- The first Linux attempt exposed a launch-write race: an already-emitted
  result was lost on broken pipe. Preserve [that failed attempt](../../evidence/2026-10-22-platform/linux-before-fix.log).
  The repair drains stdout after launch-write failure and bounds actual helper
  writes to five seconds. This is a communication timeout, not a human-wait
  timeout. A helper that never reads a large launch is terminated with failure.
- The reference form and timing example no longer let a failed autosave poison
  submission. They stop editing during terminal operations and restore retry
  controls on error.
- Lock contention is distinguished from storage/path errors. Windows skips
  unsupported Unix-style directory flushing after the already-flushed file is
  renamed. Windows directory-entry persistence across power loss is not
  promised; its runtime path remains untested.

The rendering surface keeps the same four methods. Workers and WebAssembly
use explicit CSP directives; local media streams with byte ranges. Skills own
their libraries and preview sandboxing. Electron documents the
[streaming protocol flag](https://www.electronjs.org/docs/latest/api/protocol),
and MDN documents the separate [WebAssembly CSP permission](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy).
Microsoft requires [a writable handle for FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers);
that API evidence does not substitute for Windows execution.

## Limits and next acceptance work

The [authoring guide](../../authoring.md) and example reduce setup to local
assets, four methods and one delivery route. An independent skill author or
agent has not evaluated their usability. The implementing agent performed
this run; no independent review is claimed.

Cross-packaging, compilation and Linux core execution do not establish target
desktop UI, clipboard, filesystem replacement, graphics or no-setup launch.
The [desktop handoff recipe](../desktop.md) is prepared for those checks.
Public signing/notarization, a clean Mac, power-loss recovery, every codec,
SharedArrayBuffer-dependent runtimes and arbitrary library compatibility are
outside this run. Harness and long-idle evidence remains version-specific;
it was not rerun or expanded into a universal claim. Full Fungi-native jstack
authoring remains deferred.
