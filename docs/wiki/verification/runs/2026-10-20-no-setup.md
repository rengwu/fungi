# No-setup compatibility verification

This follow-up applies the [accepted no-setup decision](../../planning.md#no-setup-delivery-decision-on-2026-10-20): use native harness capabilities, with explicit manual delivery on unsupported versions. The bounded macOS proof passed: native form/image responses returned automatically in the tested Codex, Claude, Grok, Kimi and Pi modes, and through the explicit manual fallback in OpenCode v1. The final portable Codex callback reached its originating conversation after the prior turn ended; one collection returned the submitted response and matching image.

## Scope and build

Selected features: [FEAT-sessions](../../features/sessions.md), [FEAT-interfaces](../../features/interfaces.md), [FEAT-delivery](../../features/delivery.md). The [earlier report](2026-10-20-first-proof.md) covers storage faults, cancellation, close, renderer crash, image paste and recovery. This run adds complete native form/image journeys through the installed harnesses, Kimi after authentication, and receipt-based manual collection.

Environment: macOS arm64, Go 1.26.4, Electron 44.9.0, development Node 22.19.0. Kimi now reports 2.2.0; the earlier unauthenticated attempt used 2.0.1. No harness installation, configuration edit, plugin or upgrade was performed by this run. [Source/build manifest](../../evidence/2026-10-20-no-setup/manifest.json)

The only core changes were adding `collectEnv` to launch receipts and refining CLI discovery. A later shell invocation can now collect from a custom state directory using the receipt alone. The four-method page bridge and renderer did not change.

Kimi's three-minute helper probe took 193.08 seconds including model work. Native UI probe totals were Pi 48.50, Grok 88.21, Kimi 46.15 and Claude 54.53 seconds. OpenCode's corrected launch took 8.86 seconds; its explicitly resumed collection took 7.37 seconds. These totals include model startup and desktop interaction, not just idle time.

No model status checks occurred while awaiting the human-facing UI or the three-minute helper. Grok additionally read its bundled background-task instructions before launch. Claude and Grok expose completion information in their streams. Kimi's print stream does not expose a separate notification payload; it records the initial WAITING, a later unsolicited continuation, one completed-output read and the actual response. No second prompt was supplied to the Kimi process.

## Failure and correction

The first OpenCode fixture was named `opencode.json`, a reserved harness configuration name. OpenCode added its `$schema` key; Fungi correctly rejected the resulting document as an invalid form. The model attempted that failed launch twice, and no Fungi session opened. Renaming the fixture to `opencode-form.json` resolved the collision. The failed probe is retained separately in evidence. No global configuration was changed.

Reviewing manual collection revealed that the launch receipt omitted the custom storage environment even though callbacks included it. `collectEnv` fixes that loss of context, and both the real CLI regression and OpenCode's later invocation exercised it.

## Limits

This is a bounded macOS prototype proof, not an arbitrary-duration guarantee. OpenCode v1 manual completion is an accepted fallback and is not counted as automatic return. Claude's tested headless mode is bounded; its documented local interactive background behavior has no time limit, but a long interactive run was not exercised. See [delivery research](../../research/delivery.md#no-setup-follow-up).

Sleep/wake cycles, abrupt power loss, a downloaded clean-machine/Gatekeeper launch, public signing/notarization, and Windows/Linux runtime behavior were not exercised. Windows/Linux results are compilation only. There is no permanent service or automatic restart after all relevant processes exit; explicit recovery is the accepted contract.

All completed verification windows and their session owners exited. The earlier user-edited demo remains open with its draft preserved. Raw test streams remain under `verification-output/no-setup-verification/`; evidence omits reasoning payloads and account configuration. Testing was performed by the implementing agent, without independent review.
