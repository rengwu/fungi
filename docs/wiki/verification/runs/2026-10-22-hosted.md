[sessions](../../features/sessions.md) and [interfaces](../../features/interfaces.md)
on hosted desktop operating systems. The aggregate is **Failed**: the portable
renderer did not start on every target, and a virtual display lacked WebGL.
Successful core tests do not override
that result or establish clean-machine distribution support.

## Diagnosis and repairs

Electron's [Windows initialization](https://github.com/electron/electron/blob/v44.9.0/lib/common/init.ts)
replaces `process.stdin` with an EOF-only stream. Its
[Windows entry point](https://github.com/electron/electron/blob/v44.9.0/shell/app/electron_main_win.cc)
can also attach standard streams to a console. Fungi's repair reads the
inherited input descriptor directly on Windows and sets Electron's documented
[`ELECTRON_NO_ATTACH_CONSOLE`](https://www.electronjs.org/docs/latest/api/environment-variables#electron_no_attach_console-windows)
for the renderer child. Native helpers keep their normal pipe contract. This
is an internal transport adjustment, with no new skill API or dependency.
The subsequent Windows run still encountered an empty NDJSON record before
readiness. The scanner now ignores blank lines while continuing to reject
malformed nonempty records; its regression covers blank/whitespace/CRLF lines
around a valid message. The final Windows run passes the actual round trip.

The [first repair attempt](../../evidence/2026-10-22-hosted/pipe-repair-attempt.json)
at `af7c52c` hit a test timing issue before reaching Windows rendering: a
malformed-helper test completed in 1.03 seconds but had a one-second assertion.
The [log](../../evidence/2026-10-22-hosted/windows-timing-failure.log) retains it.
The fixture now deliberately stays alive for 30 seconds while the test allows
five seconds for owner termination. This tolerates hosted process startup
while still failing if the owner waits for the broken helper's natural exit.

That attempt also exercised Ubuntu 22.04. The
[actual renderer log](../../evidence/2026-10-22-hosted/ubuntu22-initial.log)
shows 20 checks passing, including cancel/reopen/submit and the PNG hash.
WebGL failed because Chromium blocklisted it on the virtual display. This
is not a complete rendering pass; hardware-dependent APIs must be feature
detected by authored interfaces. No blocklist override or software-rendering
flag was added to make the check pass.

Ubuntu's fatal log requests a root-owned, mode-4755 sandbox helper. That is
incompatible with simply unpacking an ordinary user-owned portable archive
on this runner. Ubuntu documents
[AppArmor restrictions on unprivileged user namespaces](https://documentation.ubuntu.com/security/security-features/privilege-restriction/apparmor/),
and its [security matrix](https://documentation.ubuntu.com/security/security-features/security-features-tables/)
distinguishes 22.04 from 24.04 and later. Chromium's
[sandbox documentation](https://chromium.googlesource.com/chromium/src/+/HEAD/sandbox/linux/README.md)
describes the namespace and privileged-helper mechanisms. These sources
explain the platform constraint. The final Ubuntu 24.04 diagnostic records
`apparmor_restrict_unprivileged_userns=1` and a denied UID-map write in a
disposable namespace probe. Ubuntu 22.04 starts the renderer without host
changes; its remaining WebGL failure is recorded separately.

## Remaining acceptance boundary

The current package cannot be advertised as a no-setup renderer on every
Linux desktop. Choosing a narrower supported baseline or a Linux-specific
installation path changes the distribution promise and needs user judgment.
No installer, global AppArmor change, elevated sandbox-helper installation
or sandbox bypass has been added.

The [desktop recipe](../desktop.md) remains available for physical target
checks. Signing/notarization, clean-machine launch, arbitrary hardware,
long-duration renderer waits and universal harness resumption are not proven.
The implementing agent conducted these checks; no independent review is claimed.
