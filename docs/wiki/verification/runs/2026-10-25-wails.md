# Wails renderer fit assessment

**Failed as a replacement-equivalence proof; useful as a bounded prototype.**
Wails fits the existing process/page boundary and greatly reduces bundled
bytes. macOS and Windows pass all 21 rendering/recovery checks. Both Linux
targets pass 20, but direct local media fails. macOS/Linux browser storage
also leaks across independent sessions, and all targets expose native Wails
capabilities beyond Fungi's four-method API. Electron remains the default.

## Scope and build

The user selected Wails for practical evaluation. This run covers
[FEAT-interfaces](../../features/interfaces.md) through the actual
[session owner](../../features/sessions.md), with ordinary skill HTML,
experimental JSON forms, drafts, cancellation, reopening and image results.
It does not claim a completed production migration or universal runtime
availability. The implementing agent also verified the work; no independent
review is claimed.

Final product revision: `af42ecce6ccc089f701a243586e6f3cf49946425`, Wails
**v2.17.0**, Go **1.26.4**, Node **22.19.0** for test drivers only. The core Go
module is unchanged. A separate `renderer/go.mod` builds a native helper
launched through the existing `--exec` protocol. Assets and the page bridge
are embedded; the browser engine comes from the OS/runtime.

[Build identity](../../evidence/2026-10-25-wails/build.json) records source
hashes, local executable hashes, sizes and macOS 27.0 arm64 build 26A5368g.
The native Mac UI checks used the preceding `a18a11c` binary in a minimal
`.app` for accessibility discovery; it differs from the final binary by the
explicit JavaScript/WASM MIME repair. The final automated Mac check used
`af42ecc`. Documentation was still being written when these checks ran.

[First hosted run](https://github.com/rengwu/fungi/actions/runs/40187638667)
and [its saved metadata](../../evidence/2026-10-25-wails/first-ci.json) identify
the initial platform failures. The
[final hosted run](https://github.com/rengwu/fungi/actions/runs/40188005719)
and [saved metadata](../../evidence/2026-10-25-wails/second.json) identify all
four actual jobs. No result is inferred merely from a successful build.

## Repairs and unresolved differences

The first local build needed explicit linking to macOS
`UniformTypeIdentifiers` for the current SDK. The first recovery run then
[failed decoding artifact metadata](../../evidence/2026-10-25-wails/first-local-recovery.log):
the owner records a numeric byte count while the JS bridge uses encoded bytes.
Separate metadata/transport fields fixed it. Zero-byte restoration was also
corrected and exercised through the owner rather than a mocked binding.

The [first Windows result](../../evidence/2026-10-25-wails/wails-windows-latest-first.json)
failed dynamic import and module workers. Go's MIME lookup depends partly on
OS mappings. Explicit JavaScript and WASM content types fixed both on the
actual Windows runner; no registry change was made.

Linux direct `new Audio('./sample.wav')` returns media error code 4 on both
targets. Fetching the identical WAV and assigning a Blob URL loads its
one-second metadata successfully in the host probes. The WAV parser/plugins
were already present, so this is not simply a missing test codec. This points
to the custom-scheme media path; it does not prove every codec, playback or
Blob seek behavior. [WebKit documents the Linux GStreamer dependency](https://docs.webkit.org/Ports/WebKitGTK%20and%20WPE%20WebKit/Multimedia.html).
The prototype does not silently rewrite media URLs, replace streaming with
whole-file buffers or waive the original test.

The original fixture's “no Node or IPC” label only tested `require`, `process`
and Electron `ipcRenderer`. It is now accurately named “no Node or Electron
IPC.” That pass is not a native-isolation pass. Asset confinement and CSP
checks pass, but upstream Wails runtime APIs remain available. Navigation,
permission policies, browser-process failures and isolated macOS/Linux data
stores need a separate hardening design and runtime proof.

## Footprint and distribution boundary

Measured on this Mac with stripped Go builds:

| Artifact | Bytes |
| --- | --- |
| Wails renderer, embedded form and bridge | 7,805,746 |
| Existing Go core | 6,560,610 |
| Both executables uncompressed | 14,366,356 |
| Gzip tar containing both executables | 5,884,199 |

This is a roughly **5.9 MB prototype download**, not a complete signed release.
No Electron, browser-engine files or language runtime are in that measurement.
Runtime memory/startup benchmarks, release notices, package metadata, signing,
notarization and updater changes were not measured or completed. Native Mac
UI used a tiny `.app` wrapper around the same helper, separately fingerprinted.

macOS uses WKWebView; Windows requires WebView2; Linux requires GTK3 and
WebKitGTK 4.1 plus applicable media/runtime packages. The workflow explicitly
installs Linux build prerequisites on disposable hosted runners. It does not
establish that these packages exist on a clean user's machine or authorize
installing them there. A small download and dependency-free distribution are
different acceptance questions. The existing no-runtime-install decision is
still unresolved for the Wails migration.

The architectural fit is good: ordinary skill assets, the existing four page
methods and owner-managed persistence work without a plugin framework. Before
promotion, resolve native capabilities/private storage and renderer failure
detection, preserve Linux media behavior, define missing-runtime policy, then
qualify packaging and update/lifecycle behavior. This assessment does not
select a new fallback, weaken the page boundary or remove Electron.
